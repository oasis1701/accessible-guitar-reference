# CLAUDE.md — working notes for AI sessions on this repository

## What this is

Accessible Guitar Reference: a text-first guitar reference website for blind and visually impaired players. Live at https://accessibleguitar.com/ (the old https://oasis1701.github.io/accessible-guitar-reference/ address redirects there). The maintainer is blind and reviews everything with a screen reader; their screen-reader pass is the final gate for any user-facing change.

## Hard rules — breaking these breaks the product

1. **Text grammar** (machine-enforced on all generated text):
   - The glyphs `#`, `♯`, `♭` never appear in rendered text. Always "F sharp", "B flat" — screen readers misread the symbols.
   - The words up, down, left, and right never appear in descriptions; "higher" and "lower" always mean pitch.
   - Muted strings are always explicit ("do not play"), never implied.
   - Fingers are named (index, middle, ring, pinky, thumb), never numbered, so a number can only mean a string or a fret.
2. **No live regions or auto-announcements tied to select, combo box, or radio changes.** Arrowing through a control fires a change per step, and each announcement talks over the screen reader (maintainer-reported, 2026-08-06). Update content silently; keep status as plain text read on demand. Two sanctioned exceptions, and only these: the settings page's short "Saved" radio confirmations, and the tuner page's `role="status"` element (maintainer-approved, 2026-08-07). The tuner exception is bounded by the gates in `js/pitch.js` `createAnnouncer`, pinned by validator Phase F: announcements are driven by detected audio only — a reading stable for half a second that differs from the previous one (compared without the name sentence), at least 1.5 seconds apart (0.8 when a note arrives in tune), silent while nothing is playing, and all writes stopped by Mute while a separate plain-text paragraph stays current. Short confirmations for the tuner's own Start and Stop presses and start errors ride the same element. The metronome page has no live region at all, by design (2026-09-23): the click is the feedback, its status paragraph is plain text that changes only on the player's actions and on speed-trainer raises, and its visual beat counter is aria-hidden. Adding any announcement there needs the maintainer's approval first.
3. **Classic scripts only. No ES modules, no fetch, no build step, no npm dependencies.** The site must keep working opened straight from disk via file://. Script tag order is the dependency system.
4. **Data never contains display text; the renderer never hardcodes note names.** Every description is generated by `js/renderer.js` (pure functions, Node-loadable through `globalThis.AGR`). Settings must remain toggles, never rewrites.
5. **Never rename a data id once published.** Ids are heading anchors today and quiz/audio references tomorrow.
6. **All filenames lowercase, all URLs relative.** GitHub Pages is case-sensitive Linux serving a project subpath.

## Before every commit

```
node tools/validate.js
```

Must exit clean. It verifies the schema, recomputes every chord's real pitches to prove the declared quality and inversion, sweeps every movable shape across all 12 roots, lints all generated text in every settings combination against the grammar above, proves the tuner (Phase F): detector accuracy on synthesized waves, announcement gating on scripted timelines, and every tuner phrase, and proves the metronome (Phase G): the tick sequencer, speed trainer, and tap tempo on scripted timelines, and every metronome phrase. Phase H lints the hand-written text of every HTML page (title, body text, and aria-label, alt, title, and placeholder attributes) for the banned symbols and direction words. It has two exceptions. One is the conventions.html sentence that names the word up on purpose, pinned by its exact text. The other lets neural-dsp-keyboard-guide.html name the keys Up Arrow, Down Arrow, Left Arrow, Right Arrow, Page Up, Page Down, Left Bracket, and Right Bracket, only as the whole content of a `<kbd>` element (maintainer-approved, 2026-11-13). Do not widen either exception without the maintainer's approval.
## Architecture map

- `data/*.js` — chords and shapes assigning to `globalThis.AGR`. Schema exemplars: `open-chords.js` (fixed chords), `triads.js` (movable anchor-plus-offset shapes with roles), `barre-chords.js` (barres annotation; per-string entries stay the source of truth), `octaves.js`. The A shape major barre is fingered ring on the 4th string, pinky on the 3rd, middle on the 2nd, all two frets higher than the root fret, so the ring and pinky stay where the minor A shape puts them and only the middle finger moves; the tip keeps the flattened ring finger as the alternative. That is the maintainer's choice from playing it (2026-11-12), so do not "correct" it back to middle, ring, pinky. Both A shape barres cover all six strings, with the 6th string held by the barre but not played, so the index finger stays in place when the hand changes to an E shape at the same fret; the per-string line reads "covered by the barre, do not play", and the tip names the five-string barre with the index tip touching the 6th string as the alternative (maintainer decision, 2026-11-15, pinned by the validator). Triads cover all four string groups with one example each, and when only the two thinner strings of a triad share a fret, the index flattens across them as a small barre (maintainer-tested on the guitar, 2026-11-13).
- `js/renderer.js` — ALL text generation, including the tuner phrases (`tunerReading`, `tunerStateText`) and the metronome phrases (`metronomeStatus`, `metronomeTapText`, `metronomeBeatText`, `metronomeStateText`). Three formats (per-string, by-finger, prose) times three string namings (both, number, name). `stringLabel()` is the only place naming logic lives. Tuner readings are chromatic: they name the nearest note only ("E. In tune."), never a string identity and never an octave number (maintainer decision, 2026-08-10).
- `js/settings.js` — localStorage key `agr:settings:v1`, guarded so the site works when storage throws.
- `js/pitch.js` — pure tuner math, Node-loadable: NSDF pitch detector, frequency conversion, stability smoother, and the announcement gate (`createAnnouncer`). Validator Phase F tests it on synthesized waves and scripted timelines.
- `js/tuner.js` — browser-only microphone engine for tuner.html (getUserMedia with echo cancellation and noise suppression off but auto gain ON — quiet unplugged guitars need it and it cannot move the pitch; analyser polling, idempotent stop). `tuner.html?selftest` swaps the microphone for an inaudible oscillator so the whole loop runs with no permission, including from file://. The selftest plays F, a fretted note, so the loop proves closest-note naming.
- `js/tempo.js` — pure metronome logic, Node-loadable: config sanitizing (`sanitize`), the tick sequencer (`createSequencer`: start, peek, next, update; ticks carry time, bar, beat, sub, kind, bpm, tempoChanged), and tap tempo (`createTapTempo`). Validator Phase G tests it on scripted timelines.
- `js/metronome.js` — browser-only sound engine for metronome.html: synthesized clicks (four sounds, each kind distinct by pitch and level; the modal wood block is noise plus inharmonic partials, the older "wood" value stays as Arcade hit), a lookahead scheduler on the audio clock with a longer horizon while the tab is hidden, and an idempotent stop that closes the context. On iPhones and iPads only, output goes through a MediaStreamDestination into the page hidden `<audio id="metronome-sink">` element (plus `navigator.audioSession.type = "playback"` and Media Session play/pause handlers in page.js) because iOS stops plain Web Audio when the screen locks but keeps media playing; it falls back to the context destination when the element cannot play. Every other browser uses the context destination directly: the stream route makes the pitch wobble as the browser corrects clock drift (maintainer report, 2026-09-24). The page remembers its settings under localStorage key `agr:metronome:v1`, guarded like the site settings.
- `js/page.js` — browser-only DOM glue, dispatched by `<body data-category>`.
- HTML pages — one h3 per chord or shape sitewide (screen-reader heading-key navigation), a real list as table of contents, native form elements only, skip link, landmarks, and a visible level 2 "Site menu" heading naming the site navigation (maintainer decision, 2026-08-10; the page h1 stays the only level 1). A list of links with descriptions is a `<ul class="link-cards" role="list">` where each item holds the link in its own `<p class="link-card-name">` and a full-sentence description in a second paragraph, never the link and description joined by a dash on one line (maintainer decision, 2026-11-15, because the joined form reads rushed with a screen reader). Link text names the destination, never a raw web address, with one exception, the add-on page's download link (below). `js/page.js` wraps each chord, shape, voicing, and fretboard string in a `<div class="entry">` with no role, for the stylesheet's panels only; it must stay role-less and unlabeled so nothing new is announced. In `css/site.css`, `--control-border` is for edges that identify a control or a card and stays at 3 to 1 or better against `--bg` and `--surface` in both color schemes; `--border` is for decorative lines only.
- `neuraldsp.html` — a static page, with no scripts, for the maintainer's NVDA add-on (repository oasis1701/neural-dsp-plugins-accessibility, local clone `D:\Neural DSP\neural-access`). Its address is accessibleguitar.com/neuraldsp, shortened from neural-dsp-plugins-accessibility at the maintainer's request (2026-11-17). The old filename, `neural-dsp-plugins-accessibility.html`, is now a bare forwarding page with no site menu that sends visitors to `neuraldsp.html` and keeps the part of a link after the hash; it is the only way old links keep working on GitHub Pages, so do not delete it or grow it into a full page. The add-on page is the last site menu item, after Settings, and is spelled Neural DSP Plugins Accessibility everywhere, with a space, as the add-on's official name (maintainer decisions, 2026-11-13). Its download link is `releases/latest/download/neuralDspPluginsAccessibility.nvda-addon`, which always serves the newest release because the add-on's `build.ps1` names the package without a version (since 2026-11-13; release 0.13.1 also carries a copy under that name). Every future release must attach a file with exactly that name, or the link breaks. The download card's name is plain text, Download the latest version of the add-on directly from GitHub, and under it the link's text is its own full address, so that people hear where it goes before they open it (maintainer decision, 2026-11-20). That card's address paragraph is `class="link-card-url"`, which lets the address break anywhere so the card still fits a narrow screen. This is the one link on the site whose text is a web address. A second link goes to `releases/latest` for the release notes. A Videos from Neural DSP section after the install steps links four videos from Neural DSP's YouTube channel, and a sentence in the intro links to it by its heading id (maintainer decision, 2026-11-15). The John Petrucci performance video is the December 2021 launch video for Archetype Petrucci, the plug-in that came before the X version the add-on supports, so its card names Archetype Petrucci without the X and says nothing about versions, because the maintainer found original, older, and newer confusing (maintainer decision, 2026-11-15); do not relabel it as Petrucci X. Video links point at the single video, with no playlist parameters.
- `neural-dsp-keyboard-guide.html` — the add-on's full keyboard guide, linked from the add-on page and not in the site menu. It is a hand copy of the add-on's `addon/doc/en/readme.md` as of release 0.14.2, reworded only where the site's rules require it (no direction words outside key names, no quotation marks, level 2 headings only), so resync it by hand when the add-on's guide changes. Key names go in `<kbd>` elements.
- `conventions.html` — the reader-facing grammar contract. Keep it in sync with renderer changes.
- Page prose — written to the maintainer's writing skill, so ordinary sentences carry no colons and headings never start with What, How, Why, When, or Where. Two maintainer decisions (2026-11-11) override that: a colon stays before a verbatim sample of what the site says, such as "for example: 5th string (A)", because samples carry no quotation marks and the colon is the only audible marker; and the page title "How to read this site" stays.

## Deploy

Push to main → `.github/workflows/deploy-pages.yml` validates, then deploys to GitHub Pages (workflow build type). Manual trigger: `gh workflow run deploy-pages.yml`. The gh CLI is authenticated as `oasis1701`.

## Communicating with the maintainer

Screen-reader-first: linear prose in complete sentences, no ASCII art, no symbol-dense output, no dense tables, accidentals spelled out. When offering choices, write every option out fully in plain text with examples before any structured picker.
