# CLAUDE.md — working notes for AI sessions on this repository

## What this is

Accessible Guitar Reference: a text-first guitar reference website for blind and visually impaired players. Live at https://oasis1701.github.io/accessible-guitar-reference/. The maintainer is blind and reviews everything with a screen reader; their screen-reader pass is the final gate for any user-facing change.

## Hard rules — breaking these breaks the product

1. **Text grammar** (machine-enforced on all generated text):
   - The glyphs `#`, `♯`, `♭` never appear in rendered text. Always "F sharp", "B flat" — screen readers misread the symbols.
   - The words up, down, left, and right never appear in descriptions; "higher" and "lower" always mean pitch.
   - Muted strings are always explicit ("do not play"), never implied.
   - Fingers are named (index, middle, ring, pinky, thumb), never numbered, so a number can only mean a string or a fret.
2. **No live regions or auto-announcements tied to select, combo box, or radio changes.** Arrowing through a control fires a change per step, and each announcement talks over the screen reader (maintainer-reported, 2026-08-06). Update content silently; keep status as plain text read on demand. The settings page's short "Saved" radio confirmations are the one existing exception unless the maintainer says otherwise.
3. **Classic scripts only. No ES modules, no fetch, no build step, no npm dependencies.** The site must keep working opened straight from disk via file://. Script tag order is the dependency system.
4. **Data never contains display text; the renderer never hardcodes note names.** Every description is generated by `js/renderer.js` (pure functions, Node-loadable through `globalThis.AGR`). Settings must remain toggles, never rewrites.
5. **Never rename a data id once published.** Ids are heading anchors today and quiz/audio references tomorrow.
6. **All filenames lowercase, all URLs relative.** GitHub Pages is case-sensitive Linux serving a project subpath.

## Before every commit

```
node tools/validate.js
```

Must exit clean. It verifies the schema, recomputes every chord's real pitches to prove the declared quality and inversion, sweeps every movable shape across all 12 roots, and lints all generated text in every settings combination against the grammar above.

## Architecture map

- `data/*.js` — chords and shapes assigning to `globalThis.AGR`. Schema exemplars: `open-chords.js` (fixed chords), `triads.js` (movable anchor-plus-offset shapes with roles), `barre-chords.js` (barres annotation; per-string entries stay the source of truth), `octaves.js`.
- `js/renderer.js` — ALL text generation. Three formats (per-string, by-finger, prose) times three string namings (both, number, name). `stringLabel()` is the only place naming logic lives.
- `js/settings.js` — localStorage key `agr:settings:v1`, guarded so the site works when storage throws.
- `js/page.js` — browser-only DOM glue, dispatched by `<body data-category>`.
- HTML pages — one h3 per chord or shape sitewide (screen-reader heading-key navigation), a real list as table of contents, native form elements only, skip link, landmarks.
- `conventions.html` — the reader-facing grammar contract. Keep it in sync with renderer changes.

## Deploy

Push to main → `.github/workflows/deploy-pages.yml` validates, then deploys to GitHub Pages (workflow build type). Manual trigger: `gh workflow run deploy-pages.yml`. The gh CLI is authenticated as `oasis1701`.

## Communicating with the maintainer

Screen-reader-first: linear prose in complete sentences, no ASCII art, no symbol-dense output, no dense tables, accidentals spelled out. When offering choices, write every option out fully in plain text with examples before any structured picker.
