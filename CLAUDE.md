# CLAUDE.md — working notes for AI sessions on this repository

## What this is

Accessible Guitar Reference: a text-first guitar reference website for blind and visually impaired players. Live at https://accessibleguitar.com/ (the old https://oasis1701.github.io/accessible-guitar-reference/ address redirects there). The maintainer is blind and reviews everything with a screen reader; their screen-reader pass is the final gate for any user-facing change.

## Hard rules — breaking these breaks the product

1. **Text grammar** (machine-enforced on all generated text):
   - The glyphs `#`, `♯`, `♭` never appear in rendered text. Always "F sharp", "B flat" — screen readers misread the symbols.
   - The words up, down, left, and right never appear in descriptions; "higher" and "lower" always mean pitch.
   - Muted strings are always explicit ("do not play"), never implied.
   - Fingers are named (index, middle, ring, pinky, thumb), never numbered, so a number can only mean a string or a fret.
2. **No live regions or auto-announcements tied to select, combo box, or radio changes.** Arrowing through a control fires a change per step, and each announcement talks over the screen reader (maintainer-reported, 2026-08-06). Update content silently; keep status as plain text read on demand. Two sanctioned exceptions, and only these: the settings page's short "Saved" radio confirmations, and the tuner page's `role="status"` element (maintainer-approved, 2026-08-07). The tuner exception is bounded by the gates in `js/pitch.js` `createAnnouncer`, pinned by validator Phase F: announcements are driven by detected audio only — a reading stable for half a second that differs from the previous one (compared without the name sentence), at least 1.5 seconds apart (0.8 when a note arrives in tune), silent while nothing is playing, and all writes stopped by Mute while a separate plain-text paragraph stays current. Short confirmations for the tuner's own Start and Stop presses and start errors ride the same element. The metronome page has no live region at all, by design (2026-09-23): the click is the feedback, its status paragraph is plain text that changes only on the player's actions and on speed-trainer raises, and its visual beat counter is aria-hidden. Adding any announcement there needs the maintainer's approval first.
3. **Classic scripts only. No ES modules, no fetch, no build step, no npm dependencies.** The site must keep working opened straight from disk via file://. Script tag order is the dependency system.
4. **Data never contains display text; the renderer never hardcodes note names.** Every description is generated by `js/renderer.js` (pure functions, Node-loadable through `globalThis.AGR`). Settings must remain toggles, never rewrites.
5. **Never rename a data id once published.** Ids are heading anchors today and quiz/audio references tomorrow.
6. **All filenames lowercase, all URLs relative.** GitHub Pages is case-sensitive Linux serving a project subpath.

## Before every commit

```
node tools/validate.js
```

Must exit clean. It verifies the schema, recomputes every chord's real pitches to prove the declared quality and inversion, sweeps every movable shape across all 12 roots, lints all generated text in every settings combination against the grammar above, proves the tuner (Phase F): detector accuracy on synthesized waves, announcement gating on scripted timelines, and every tuner phrase, and proves the metronome (Phase G): the tick sequencer, speed trainer, and tap tempo on scripted timelines, and every metronome phrase.

## Architecture map

- `data/*.js` — chords and shapes assigning to `globalThis.AGR`. Schema exemplars: `open-chords.js` (fixed chords), `triads.js` (movable anchor-plus-offset shapes with roles), `barre-chords.js` (barres annotation; per-string entries stay the source of truth), `octaves.js`.
- `js/renderer.js` — ALL text generation, including the tuner phrases (`tunerReading`, `tunerStateText`) and the metronome phrases (`metronomeStatus`, `metronomeTapText`, `metronomeBeatText`, `metronomeStateText`). Three formats (per-string, by-finger, prose) times three string namings (both, number, name). `stringLabel()` is the only place naming logic lives. Tuner readings are chromatic: they name the nearest note only ("E. In tune."), never a string identity and never an octave number (maintainer decision, 2026-08-10).
- `js/settings.js` — localStorage key `agr:settings:v1`, guarded so the site works when storage throws.
- `js/pitch.js` — pure tuner math, Node-loadable: NSDF pitch detector, frequency conversion, stability smoother, and the announcement gate (`createAnnouncer`). Validator Phase F tests it on synthesized waves and scripted timelines.
- `js/tuner.js` — browser-only microphone engine for tuner.html (getUserMedia with echo cancellation and noise suppression off but auto gain ON — quiet unplugged guitars need it and it cannot move the pitch; analyser polling, idempotent stop). `tuner.html?selftest` swaps the microphone for an inaudible oscillator so the whole loop runs with no permission, including from file://. The selftest plays F, a fretted note, so the loop proves closest-note naming.
- `js/tempo.js` — pure metronome logic, Node-loadable: config sanitizing (`sanitize`), the tick sequencer (`createSequencer`: start, peek, next, update; ticks carry time, bar, beat, sub, kind, bpm, tempoChanged), and tap tempo (`createTapTempo`). Validator Phase G tests it on scripted timelines.
- `js/metronome.js` — browser-only sound engine for metronome.html: synthesized clicks (three sounds, each kind distinct by pitch and level), a lookahead scheduler on the audio clock with a longer horizon while the tab is hidden, and an idempotent stop that closes the context. The page remembers its settings under localStorage key `agr:metronome:v1`, guarded like the site settings.
- `js/page.js` — browser-only DOM glue, dispatched by `<body data-category>`.
- HTML pages — one h3 per chord or shape sitewide (screen-reader heading-key navigation), a real list as table of contents, native form elements only, skip link, landmarks, and a visible level 2 "Site menu" heading naming the site navigation (maintainer decision, 2026-08-10; the page h1 stays the only level 1).
- `conventions.html` — the reader-facing grammar contract. Keep it in sync with renderer changes.

## Deploy

Push to main → `.github/workflows/deploy-pages.yml` validates, then deploys to GitHub Pages (workflow build type). Manual trigger: `gh workflow run deploy-pages.yml`. The gh CLI is authenticated as `oasis1701`.

## Communicating with the maintainer

Screen-reader-first: linear prose in complete sentences, no ASCII art, no symbol-dense output, no dense tables, accidentals spelled out. When offering choices, write every option out fully in plain text with examples before any structured picker.
